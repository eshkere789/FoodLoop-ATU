# FoodLoop АТУ: прототип платформы

Учёт пищевых остатков в столовых, буфетах и лабораториях университета и продажа излишков со скидкой.
Все данные синтетические. Сайт статический (без сборки), работает на GitHub Pages.

## Быстрый старт (демо-режим, ничего настраивать не нужно)
```bash
cd foodloop
python3 -m http.server 8000      # открыть нужно через сервер, двойной клик по index.html не сработает (ES-модули)
# затем http://localhost:8000
```
В демо-режиме «БД» живёт в localStorage браузера и повторяет логику `supabase/schema.sql`. Сбросить: ссылка «Сбросить демо-данные» внизу страницы.
Логины на странице входа (кнопки «Войти как…»), общий пароль `demo1234` (заглушка в `js/config.js`).

## Демо-сценарий на 5 минут
1. Гость: **Витрина** (6 живых лотов на сегодня), фильтры (без глютена, только лаборатории), карточка лота с составом.
2. `resp_5` (кофейня): **Форма учёта** → «Йогурт», 10 порций, причина «Срок годности истекает завтра», галочка «состав проверен» → отправить. QR-плакаты: раздел «QR-коды».
3. `reviewer_1`: **Проверка** → открыть отчёт кофейни → автопроверки → **Принять** (создаются лоты с ценой по правилу скидок).
4. `student_1`: на **Витрине** найти йогурт кофейни → **Забронировать** 3 порции → код выдачи. В «Уведомлениях» видно сообщение, которое отправил бы бот.
5. `resp_5`: **Выдача** → ввести код → «Выдано».
6. `student_1`: «Мои брони» → «Оставить отзыв». `resp_5`: «Отзывы» → ответить.
7. `head` (руководство): **Дашборд**: KPI, 4 графика, рекомендация про плов по пятницам, до/после запуска, выгрузка Excel и печать. **Реестр** с фильтрами.
Лаборатории: `resp_4` (допуск действует) и `resp_8` (подайте отчёт с датой после 31.03.2027: допуск просрочен, лот не создастся).

## QR-коды: вход и форма учёта с телефона
- **Страница входа** и **форма учёта** («Заполнить с телефона») показывают QR; раздел **QR-коды** содержит QR входа, витрины и форм всех организаций (плакат для печати).
- Гость, отсканировавший QR формы, попадает на вход, а после входа сразу в нужную форму.
- На `localhost` телефон сайт не откроет: в блоке «Изменить адрес сайта для QR» укажите адрес компьютера в Wi-Fi (например `http://192.168.1.5:8000/`, сервер запускать как `python3 -m http.server 8000 --bind 0.0.0.0`) или опубликованный адрес. Он хранится в localStorage.
- В демо-режиме данные лежат в браузере каждого устройства, поэтому отчёт с телефона на компьютере не виден; для общей базы нужен режим Supabase.
- Код: `js/phoneqr.js`.

## Структура
```
index.html, css/            интерфейс (mobile-first)
js/app.js                   роутер, меню по ролям
js/phoneqr.js              QR для входа/формы с телефона (адрес сайта, карточка QR)
js/api.js, config.js        выбор бэкенда: mock или supabase
js/backend-mock.js          демо-бэкенд в браузере (логика = SQL)
js/backend-supabase.js      бэкенд на Supabase (чтение через RLS, запись только через RPC)
js/analytics.js             агрегации дашборда и рекомендации
js/views/*.js               экраны: login, showcase, lot, mybookings, form, reports, report, review,
                            registry, pickup, dashboard, feedback, qr, notifications
data/*.json                 демо-данные (из CSV), libs/ — библиотеки локально
supabase/                   schema.sql, seed, import_csv.sh, create_demo_users.mjs, тесты схемы
bot/                        Telegram-бот (long polling)
tests/                      автотесты
```

## Режимы и публикация
- **GitHub Pages:** запушить папку в репозиторий, Settings → Pages → ветка `main`, корень. Сайт статический, работает в демо-режиме сразу.
- **Supabase:** см. `supabase/README.md`, затем `MODE: 'supabase'` в `js/config.js`.
- **Telegram-бот:** `cd bot && pip install -r requirements.txt`, заполнить `.env.example` → `.env`, `export $(cat .env | xargs) && python3 bot.py`. Бот нужен только в режиме Supabase (читает таблицу `outbox`). Токен и service_role key не коммитить.

## Что НЕ проверено (проверьте сами)
- Реальный проект Supabase (Auth/GoTrue, `create_demo_users.mjs`, настройки URL, лимиты бесплатного тарифа, домен email для учёток).
- Реальный Telegram (токен, доставка сообщений).
- Публикация на GitHub Pages, другие браузеры кроме Chromium.
- Нагрузка и параллельные брони при многих пользователях (в БД есть блокировка строки, но нагрузочно не проверялось).

## Ограничения прототипа
- В демо-режиме данные хранятся только в вашем браузере, «общей» БД нет.
- Остаток, не выданный покупателям, на дашборде считается списанием.
- Коэффициент CO₂ 2,5 кг/кг, доли переработки и скидки — допущения (`settings`, правила в `_accept_report`).
- Часовой пояс: лоты «на сегодня» считаются по дате сервера (`current_date`, UTC) и по локальной дате браузера в демо-режиме.
- Платежей нет: оплата при получении.
